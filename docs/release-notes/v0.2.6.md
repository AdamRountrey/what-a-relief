# what-a-relief v0.2.6

## Inverse Light Support

- Lights with fewer than 64 supported, unclipped reduced fitting pixels are
  omitted before inverse fitting and the training/withheld split. A single
  poorly supported photo no longer prevents refinement of an otherwise usable
  stack. At least six eligible lights and well-conditioned training directions
  are still required.
- `result.json` records per-light support, omitted lights, and original input
  indices. Selection uses input validity and geometry support, not fitting
  errors. Clipping rules and reconstruction acceptance gates are unchanged.
- GUI quality choices now show their grid limits and iteration budgets:
  Preview 64/12, Standard 128/24, and High detail 256/50. Standard remains the
  default; printable mesh sampling is independent of this optimization grid.

## Printable Inverse Solids

- Selecting printable export now also creates
  `inverse/inverse_printable_surface.ply` when inverse processing completes.
  It uses the accepted full-resolution inverse height, or the retained baseline
  if validation rejects refinement. Unvalidated candidates are never selected
  automatically for printable output.
- The same millimeter scale, base thickness, Z exaggeration, mesh sampling,
  optional enclosed-hole filling, and single edge-connected component policy
  apply to regular and inverse solids. Original height and normal products
  remain unchanged by printing-only edits.
- A PLY header annotation and `inverse_printable_surface.json` identify the
  height source and print settings. Optional filling also writes an audit mask.
  Inverse outputs are staged together; a mesh-export failure does not replace
  the previous inverse output directory with a partial package.

## Validation and Limits

Application release gates cover normal solving, IO, printable topology, backend
contracts, and end-to-end workflows. New deterministic inverse-export tests
check accepted/rejected results, float-height orientation, scale, sampling,
base thickness, connectedness, watertight edge incidence, provenance, and
failure-safe replacement. These tests do not measure reconstruction accuracy.

The real CPU renderer regression includes eight usable views plus two fully
clipped views. It retains the original tilt-recovery improvement, while an
already-correct surface rejects unnecessary correction. On a 40-photo fish
stack, a read-only support check retained all forty lights at 256 x 170 versus
twenty at 128 x 85. This is eligibility evidence, not a completed high-resolution
inverse solve or an accuracy comparison. High detail also increases sampling
and iterations, so it can be substantially more expensive.

Physical XY scale does not establish calibrated height accuracy. Inverse
rendering remains experimental; approximate camera, lighting, and reflectance
models can limit results. Watertight topology does not guarantee successful
slicing or adequate thickness for every printer.

## Windows Downloads

- `what-a-relief-0.2.6-setup.exe`: application installer.
- `what-a-relief-0.2.6-portable-windows.zip`: application, DLLs, models, and docs.
- `what-a-relief-0.2.6-mitsuba-backend-setup.exe`: optional self-contained
  inverse-rendering runtime. Dependency versions are unchanged from v0.2.5;
  the updated worker is shipped with the main application.

Close running application windows before upgrading. Installers are unsigned
and may trigger a publisher/SmartScreen warning. Users do not need a separate
Python or Anaconda installation. An existing v0.2.5 Mitsuba runtime remains
compatible with the v0.2.6 application.
