# Optional Mitsuba Backend

This directory is the versioned worker side of the optional what-a-relief
inverse-rendering feature. The ordinary application, classical photometric
solve, tests, installer, and portable package do not import Python or Mitsuba.
They include only this worker interface. The runtime is installed into a
separate isolated environment.

The worker accepts only a schema-versioned JSON job generated by
what-a-relief. It writes all candidate and accepted products beneath the
job's `inverse` staging directory and never replaces the baseline normal,
height, or mesh files.

Input observations are source-independent 16-bit linear grayscale PNGs made
from the same post-radiometric float stack used by the classical solver. The
job retains the original source paths and common normalization divisor for
audit, but the worker never opens the original TIFF, PNG, JPEG, or
vendor-format images. The temporary observation directory is removed after
the backend exits.

Supported execution paths are:

- `cuda_ad_rgb` with Mitsuba's `direct_projective` integrator and Adam;
- `llvm_ad_rgb` with the same integrator and optimizer using the add-on's
  private LLVM runtime.

Every device choice is live-probed before a job. `Auto` tries CUDA and then
LLVM CPU. Merely listing a Mitsuba variant is not treated as availability.
The self-contained Windows add-on bundles LLVM 18.1.6, the version documented
for this Dr.Jit line, so CPU-only systems need no separate toolchain. Both
compute paths use the same renderer, objective, parameterization, and
acceptance gate.

The geometry is a fixed-XY height field initialized from the classical solve.
Only a coarse bilinear Z correction is optimized, preserving the baseline's
fine detail and avoiding free 3D vertex tangling. Appearance is fitted as
spatially varying nonnegative diffuse, narrow-GGX, and broad-GGX rough-plastic
bases. A deterministic subset of lights is withheld; a candidate is exported
as the accepted inverse height only when training improves without materially
worsening the withheld views or violating correction bounds.

This remains experimental. Projective Sampling currently requires a
perspective sensor, so a long-distance narrow-field perspective camera is used
as a weak-perspective approximation to the fixed microscope view. LEDs are
idealized as directional or isotropic point emitters, and the near-field Z
datum assumes the median masked integrated height lies on the ring-light
reference plane. A good image loss does not establish metrological height
accuracy.

## Windows installation

Run `what-a-relief-<version>-mitsuba-backend-setup.exe`. It installs an
application-local CPython runtime, the exact package versions in
`requirements.lock.txt`, and LLVM under
`%LOCALAPPDATA%\Programs\what-a-relief-mitsuba`. No Python, pip, Conda,
Anaconda, or LLVM installation is required. The installer requires the bundled
LLVM CPU path to pass a live render probe and also records whether NVIDIA CUDA
is available. The main application finds this location automatically after a
restart, or advanced users can locate another compatible private runtime.

For output folders on Windows network shares, renderer-facing bitmap and mesh
access is proxied through local temporary files because Mitsuba's file layer
does not preserve all UNC paths. Completed products are still published to the
selected output folder, and temporary renderer files are removed after the run.

Release maintainers build the add-on with
`scripts\build-mitsuba-backend-installer.ps1`. CPython, wheel, and LLVM inputs
are version-pinned and SHA-256 checked before packaging. Their license files
remain in the installed runtime.
